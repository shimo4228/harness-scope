prose-mod 設計図

global の harness（skill・agent・rules・ツール）を、global に置いた名前付き profile 1 つで repo ごとに ON/OFF する Claude Code の Mod。執筆 repo には「使うものだけ」を見せる allowlist が中心で、執筆はその profile の 1 つ（writing）になる。

1. 何がどこを通るか

Mod は Claude Code が組み立てた文脈と、モデルの間に入る。repo には profile の名前だけを置き、中身は global の 1 か所にある。Mod は会話の始まりにそれを読み、4 種類の部品をそれぞれの event で絞る。

2. なぜ allowlist か

ネイティブ設定も repo ごとに部品を外せるが、どれも「これを外す」と名前を並べる denylist で、出どころによって外せる粒度が違う。Mod の allowlist は「これだけ使う」と書き、出どころを問わず効く。

skill の出どころ件数（C0）ネイティブ（repo の settings）Mod の allowlist
user（~/.claude/skills）44名前ごとに外せる（skillOverrides）書いたものだけ残る
plugin19plugin 丸ごとのみ（enabledPlugins）1 つずつ選べる
built-in（simplify など）17未確認1 つずつ選べる
claude.ai から同期（anthropic-skills:*）14未確認1 つずつ選べる
repo 自身（.claude/skills）7外さない外さない（書き忘れても残る）
あとから global に足した skill—denylist に足すまで入ってくる書くまで入らない

agent も同じ形で、ネイティブは Agent(name) の deny を名前ごとに並べる。rules とツールはネイティブでも外せる（claudeMdExcludes・deny）が、profile と settings の 2 か所に分けると「なぜ OFF か」を 2 か所で調べることになるので、同じ profile で扱う。

3. skill を隠すと何が変わるか

skill 一覧には予算（context の 1%）があり、一覧は常にその上限まで使われる。超えた分は、一部の skill の説明が削られて名前だけになる。だから skill を外しても字数はほぼ減らず、空いた分で削られていた説明が戻る。効くのは量ではなく中身で、関係ない skill が消え、使う skill の説明が欠けずに載る。

4. profile の書き方

global に置く profile（中身はここだけ）

{
  "skills":       { "allow": ["writing-ecosystem",
                              "prose-translation",
                              "headline-craft"] },
  "agents":       { "allow": ["Explore", "general-purpose"] },
  "instructions": { "deny":  ["~/.claude/rules/common/testing.md"] },
  "tools":        { "deny":  ["LSP", "mcp__claude_ai_Slack__*"] }
}

repo に置く選択ファイル（名前だけ）

{ "profile": "writing" }

repo 側には中身を書けない。clone してきた repo が、あなたの安全側の rules を黙って外せないようにするため。選べるのは、自分で定義した profile と Mod 同梱の profile だけ。

5. 守ること・できないこと

不変条件（テストで固定）

  • profile を選んでいない repo、壊れた profile、知らない形式は全部素通し
  • 同じ入力と profile なら出力も同じ（prompt cache を壊さない）。残した項目はバイト単位で元のまま
  • repo 自身の skill・agent・指示ファイル、managed の指示、hook と他 plugin の出力には触れない
  • 外部通信・プロセス起動・モデル呼び出しはしない。読むのは profile と選択ファイルだけ
  • 確認コマンド /prose-mod は画面に出し、モデルには返さない（OFF の名前を教えないため）

既知の限界（README に書く）

  • 見せるかどうかの制御で、強制ではない。モデルが SKILL.md を直接読めば読める
  • paths: 付きの rule など、後から付く指示ファイルは外れない
  • OFF のツールはネイティブの deny のように完全には消えない（v0.2 で同期）
  • profile の変更は新しい会話か /clear から効く
  • built-in と同じ名前の user の agent（例: Explore）を OFF にすると、built-in にも戻らない
